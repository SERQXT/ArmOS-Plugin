# Outcome discovery brief (survey → five themes)

Maps **survey columns and comments** to a **short build brief** that feeds **C / D / F**. This is **not** a substitute for human discovery — it grounds automation in what the customer already said.

## Five themes (conceptual)

Where the schema allows, extract or infer:

1. **Winning state** — what “good” looks like for the business.  
2. **Tuesday user** — primary persona and their weekly job-to-be-done.  
3. **Hero metric** — the one number or signal that must be right.  
4. **Least-confident decision** — where the user hesitates today.  
5. **Wow factor** — what would make them tell someone else.

## Process

1. List **verbatim** quotes or field values per theme (with field name).  
2. Mark **confidence**: high / medium / low / missing.  
3. **Conflicts** — if survey contradicts itself, note both and defer to discovery.  
4. **One-page brief** — ≤ 400 words: bullets, not essay.

## Output artifact

- `500apps/{account}/objective/OUTCOME-BRIEF.md` (or merge into north-star section if product prefers a single file — **be consistent per account**).

## Relation to NORTHSTAR.md

- **OUTCOME-BRIEF** = survey-grounded extraction.  
- **NORTHSTAR** = committed direction for the build; may tighten language from the brief.
